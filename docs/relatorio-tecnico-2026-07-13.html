Sumário

Esta sessão evoluiu o redesign Next.js do site Neroes em duas frentes: correções estruturais herdadas do WordPress (navegação, equipa, calculadora, logótipos de parceiros) e a construção de um hero completamente novo — um cérebro processual em WebGL com uma narrativa em quatro atos controlada por scroll, uma camada de 2000 partículas 2D que muda de forma ao longo da narrativa, e efeitos de pós-produção (grão, halação, aberração cromática). A sessão terminou com duas novas secções de produto e testemunhos logo a seguir ao hero. Todo o código passa em typecheck, lint e build antes de cada entrega.

Hero 3D — o cérebro concluído

src/components/BrainHero.tsx · src/components/hero/SynapseGraph.ts · src/components/hero/displacementShader.ts

Nuvem de pontos processual (buildBrain()) renderizada com shaders GLSL próprios (POINT_VERT/POINT_FRAG), com deslocamento por ruído simplex e um grafo de sinapses independente:

  • Grafo de sinapses com amostragem tipo Poisson-disk (nós bem espalhados), arestas por 3-vizinhos-mais-próximos (kNN), pulsos ambiente a cada ~500ms e pulsos disparados ao passar o cursor sobre um nó (hit-testing em screen-space).
  • Aberração cromática (post-process de 2 passes) só corre no Ato III — fora dessa janela, o custo extra nem existe.
  • Redução para mobile (<768px): 5000 pontos em vez de 9000, 50 nós em vez de 90, sem deslocamento nem aberração cromática.
  • Resize com debounce de 150ms; um único requestAnimationFrame para toda a cena.

Narrativa em 4 atos concluído

src/components/hero/useScrollNarrative.ts · useMouseParallax.ts · GrainOverlay.tsx · CursorHalo.tsx · AtmosphericBackdrop.tsx

Progresso de scroll suavizado por interpolação (fator 0.04) guardado numa ref — sem re-render por frame; o estado React (act) só é atualizado a cada ~100ms para os consumidores JSX. Paralaxe do rato é independente do scroll (interpolação 0.08). Por cima de tudo, quatro camadas "cinema grade": grão (canvas a 12fps), halação âmbar, LUT azul de marca a 3%, e scanline a 2%.

Sistema de partículas 2D concluído

src/components/hero/ParticleMorph.tsx

2000 partículas em Canvas 2D, sobrepostas à cena WebGL sem tocar em BrainHero.tsx. Quatro formas pré-computadas (toroide, galáxia, invólucro do cérebro, matriz de pontos) que se misturam de acordo com o progresso do scroll, mais interação magnética com o rato.

  • Projeção em perspetiva escrita à mão (sem biblioteca) — FOCAL=640, CAM_DIST=430.
  • Desenho via fillRect em vez de arc() — medido como mais rápido para 2000 partículas por frame.
  • Um único observer de interseção pausa o RAF quando a secção sai do ecrã; devolve null sob prefers-reduced-motion.

Bugs corrigidos

THREE.Clock consumido duas vezes por frame velocidade dos pulsos estava errada

Chamar clock.getElapsedTime() e depois clock.getDelta() no mesmo frame avança o relógio interno duas vezes. Corrigido para uma única chamada a getDelta(), lendo clock.elapsedTime diretamente para o tempo total.

Aberração cromática sempre ativa ~14.5fps → ~20+fps (headless)

O passe de post-processing (render-target + quad fullscreen) corria em todos os frames, mesmo fora do Ato III onde é invisível. Agora só corre quando aberration > 0.00005.

Partículas quadradas em vez de circulares

THREE.PointsMaterial usa sprites quadrados por omissão. Corrigido com um fragment shader próprio (discard fora do raio 0.5).

.gitignore com regra nunca aplicada

Um echo anterior tinha concatenado .claude/ na linha de yarn-error.log* sem quebra de linha, produzindo um glob inválido — .claude/ nunca foi realmente ignorado. Corrigido para linhas separadas.

Aprendizagens técnicas

Padrões que vieram desta sessão e que valem para o resto do projeto.

01

Em qualquer loop de requestAnimationFrame, usar refs em vez de estado React para valores por-frame; estado só para mudanças discretas e "throttled" que a UI precisa de ler (ex.: o número do ato).

Porquê: estado React em cada frame força re-render 60x/s; refs não.

02

Efeitos caros (como a aberração cromática) devem ser condicionados à janela em que são visíveis, não correr sempre "por garantia".

Porquê: o mesmo efeito invisível fora do Ato III estava a custar ~30% de FPS.

03

Quando faltam ativos reais (logótipos, vídeos), construir a estrutura de código completa e tipada com caminhos de substituição claramente assinalados, em vez de bloquear a entrega ou inventar conteúdo.

Porquê: permite entregar o resto do trabalho e trocar o ficheiro depois sem tocar em código.

04

Nunca inventar estatísticas ou citações — todos os KPIs usados no hero (+111%, +21.7%, -14.2%) vêm da página de Ciência já verificada, não de números sugeridos em prompts externos.

Porquê: prompts vindos de outras ferramentas (Lovable/Fable) por vezes sugeriam números fabricados.

05

Prompts escritos para outra stack (Vite/TanStack Start, imagens estáticas) são adaptados à arquitetura real (Next.js + Three.js), preservando a intenção criativa em vez de construir um sistema paralelo incompatível.

Porquê: evita duplicar lógica e manter dois sistemas de animação a competir pelo mesmo canvas.

06

Antes de fazer push, confirmar com git rev-list --left-right --count se o branch remoto realmente diverge — evita usar --force quando um push normal chega.

Porquê: --force sem necessidade arrisca apagar histórico de outra pessoa.

Workflow de verificação

Repetido antes de cada entrega significativa nesta sessão.

npm run typecheck → npm run lint → npm run build → reiniciar o servidor de desenvolvimento (.next limpo) → verificação visual com Playwright, incluindo isolar camadas individuais do canvas quando o resultado composto era ambíguo (ex.: esconder todos os canvas menos um para confirmar a forma das partículas isoladamente).

Hydration mismatch sob prefers-reduced-motion limitação conhecida

useReducedMotion() assume false no servidor; num cliente com o SO já configurado para movimento reduzido, o React descarta e regenera a árvore. É um padrão pré-existente, usado em todo o projeto desde antes desta sessão — não corrigido agora porque exige um refactor mais amplo de segurança-SSR; sinalizado ao utilizador como limitação conhecida, não bloqueante.
